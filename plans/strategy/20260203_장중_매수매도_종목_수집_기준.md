# 장중 매수/매도 종목 수집·기준 (전문 투자자 관점)

## 1. 현황 요약

- **매수 대상**: 09:10 1회, **전일(basDt)** 기준 TB_SIGNAL_SCORE + PositionSizingService.getRecommendations. 즉 **장전(08:00 팩터 계산)** 결과만 사용하며, **장중에 새로 수집·스크리닝하는 매수 후보** 파이프라인은 없음.
- **매도 대상**: **보유 포지션**만. 장중 5분마다 보유 종목의 현재가/당일 고가를 RealtimeMarketDataService로 조회해 청산 규칙 평가. “장중에 매도할 종목 후보를 수집·기준으로 선정”하는 구조는 없음(이미 보유 종목만 대상).

전문 투자자 관점에서 **장중에 매수/매도할 종목**을 정하기 위해서는 (1) **무엇을 수집할지**, (2) **어떤 기준으로 선정할지**를 명확히 할 필요가 있음.

---

## 2. 수집(Collection)

### 2.1 장중 매수 후보 수집

| 항목 | 설명 | 소스/주기 | 비고 |
|------|------|-----------|------|
| **실시간 시세** | 현재가, 시가, 당일 고/저, 누적 거래대금 | 한국투자증권 현재가 API, (선택) WebSocket | 변동성 돌파·Trailing Stop 계산에 필수. 5분마다 또는 이벤트 기반 |
| **당일 시가·전일 범위** | 변동성 돌파 Target = 시가 + (전일 High−Low)×k | 일봉(전일) + 당일 시가 수집 | 9:00~10:00 구간에서 돌파 여부 판단용 |
| **장중 거래대금** | 누적 거래대금(또는 시간대별) | 현재가 API 내 거래대금 또는 별도 순위 API | 유동성 필터(예: 300억 이상) 장중 적용 |
| **수급(투자자별 매매)** | 외국인/기관 당일 순매수 금액 | 한국투자증권 투자자별 매매동향 API | 10분/30분 단위 수집 시 수급 강도 갱신 |
| **호가/체결** | 매수/매도 호가, 체결강도 | WebSocket 또는 체결/호가 전용 API | 체결강도 120%+ 등 단기 시그널 보강용 |
| **뉴스/공시** | 장중 속보, 수시공시 | DART/연합뉴스 등 (§7 원천) | 이벤트 기반 매수/매도 트리거 |

**수집 주기 제안**

- **매수 후보 풀 갱신**: 09:00 시가 반영 후 1회 + (선택) 10:00, 11:00 재스크리닝.
- **실시간 시세(청산용)**: 기존처럼 5분마다 보유 종목만 조회 유지.
- **수급/거래대금**: 10분~30분 간격으로 “감시 유니버스” 종목만 조회(전 종목은 API 한도·비용 부담).

### 2.2 장중 매도 대상 수집

| 항목 | 설명 | 소스/주기 | 비고 |
|------|------|-----------|------|
| **보유 포지션 + 현재가/당일 고가** | 청산 규칙(Trailing, -5%, 전저점, RSI 등) 평가용 | 기존 RealtimeMarketDataService 5분마다 | 현재 구현 유지 |
| **(확장) 손절/익절 대기 목록** | 아직 포지션 미보유지만 “가격 도달 시 매도”할 조건주 | 사용자/시스템이 정한 조건 + 실시간 시세 | 조건부 매도(OTO 등) 연동 시 수집·감시 대상 정의 필요 |

현재는 “매도할 종목” = 보유 포지션으로 충분. “손절/익절 대기 목록”은 별도 기능으로 확장 시 위 표와 같이 수집 항목 정의 권장.

## 3. 기준(Criteria)

### 3.1 장중 매수 대상 선정 기준

**1단계: 유니버스(감시 대상) 축소**

- **유동성**: 장중 누적 거래대금 ≥ 임계값(예: 300억 원, 시초가 대응 `liquidity-min-trd-val-opening`과 통일).
- **전일 시그널 보유 여부**: 장전 TB_SIGNAL_SCORE(전일 또는 당일 08:00 기준)에 있는 종목만 감시할지, 또는 **전 종목 중 유동성만 통과한 뒤 시그널 없이 변동성 돌파만** 쓸지 정책 선택.
- **(선택) 업종/섹터**: 주도 업종(Sector RS) 내 종목만 감시(데이터 수집 후 적용).

**2단계: 장중 진입 조건(매수 시그널)**

- **변동성 돌파**: 당일 현재가 ≥ 시가 + (전일 High − 전일 Low) × k. k는 동적(0.3~0.7) 또는 고정(0.5). **시간대 제한**: 9:00~10:00만 허용 등으로 슬리피지·허위 돌파 완화.
- **수급 강도**: (선택) 장중 누적 외국인/기관 순매수 금액이 시총 대비 N% 초과 시 가산 또는 필수.
- **체결강도**: (선택) 체결강도 ≥ 120% 등. 데이터 수집 후 적용.
- **한도**: 종목당 1회 진입, 일일 최대 매수 종목 수(예: 5~10종목) 상한.

**3단계: 제외 조건**

- 이미 해당 종목 보유 중이면 중복 매수 방지(또는 상한 비중까지만).
- 당일 고가 대비 -3% Trailing 등 “같은 날 청산” 규칙과 충돌하지 않도록 진입 시각·목표 수익/손절 정합성 유지.

### 3.2 장중 매도 대상 선정 기준

- **현행 유지**: “매도할 종목” = **보유 포지션 전부**. 별도 “매도 후보 수집” 없이, 보유 종목에 대해 아래만 적용.
- **청산 규칙 우선순위**(기존 ExitRuleEvaluator 유지):  
  KR 단기: -5% 고정 손절 → 전저점 이탈 → RSI≥70 익절 → -3% Trailing Stop → Time-Cut.  
  중기: -10% 손절.  
  장기: (현재 스텁) 매도 시그널 없음.
- **(확장) 조건부 매도**: “현재가 ≥ 목표가” 또는 “현재가 ≤ 손절가”인 **미보유 종목**을 “매도 대기”로 두는 기능을 넣을 경우, 해당 조건 + 종목 코드를 “매도 감시 목록”으로 저장하고, 장중 수집한 현재가로 조건 충족 시 알림 또는 주문 생성.

## 4. 구현 시 연동 포인트

- **수집**  
  - 신규: “장중 매수 감시 유니버스” 테이블 또는 캐시(종목 리스트 + 시가, 전일 High/Low, k).  
  - 기존: RealtimeMarketDataService(현재가/당일 고·저), 한국투자증권 API(거래대금, 투자자별 매매 등).  
  - FactorCalculationService의 “한국장 9:00~10:00 시간대별 변동성” TODO와 연계 시 장중 수집 데이터 사용.

- **기준**  
  - “장중 매수 후보” 필터: UniverseFilterService 확장 또는 전용 `IntradayUniverseFilter`(유동성, 시그널 보유, 시간대).  
  - 변동성 돌파 충족 시 PositionSizingService/파이프라인과 연동해 1회 매수 주문 생성(중복 진입 방지, 일일 상한 적용).

- **설정**  
  - application.yml 또는 전략 레지스트리: `intraday.liquidity-min-trd-val`, `intraday.volatility-breakout-window-start/end`, `intraday.max-buy-candidates-per-day` 등.
