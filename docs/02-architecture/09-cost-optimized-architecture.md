# 비용 최적화 아키텍처

## 개요

초기 투자 금액이 크지 않은 상황을 고려하여 유지비를 최소화한 아키텍처입니다.
아키텍처 문서(`03-ai-redesign.md`)의 목표는 유지하되, 비용 효율적인 구성으로 재설계합니다.

## 비용 최적화 전략

### 1. 통합 서버 구성
- 여러 서버를 1-2대로 통합
- 마이크로서비스 → 모놀리식 (필수 기능만)
- 불필요한 인프라 제거

### 2. 클라우드 비용 절감
- 스팟 인스턴스 활용
- 예약 인스턴스 (장기 사용 시)
- 자동 스케일링 최소화

### 3. 오픈소스 우선
- 상용 서비스 대신 오픈소스 사용
- Vector DB: Pinecone (유료) → Weaviate (오픈소스)
- 모니터링: 상용 대신 Prometheus (오픈소스)

### 4. AI 서비스 최소화
- 초기에는 CPU만 사용
- GPU는 필요 시에만 추가
- 모델은 경량 버전 사용

## 아키텍처 단순화

### 원래 설계 (고비용)
```
클라이언트 레이어 (Next.js, React)
    ↓
API Gateway (Spring Cloud Gateway)
    ↓
마이크로서비스 (3개 서버)
    ↓
AI/ML 서비스 (3개 서버, GPU)
    ↓
데이터 레이어 (MariaDB, Redis, TimescaleDB)
    ↓
스트리밍 (Kafka)
    ↓
데이터 파이프라인 (Airflow)
    ↓
Vector DB (Pinecone)
```

### 최적화 설계 (저비용)
```
클라이언트 레이어 (React SPA)
    ↓
Spring Boot (모놀리식)
    ↓
로컬 MariaDB + Redis
    ↓
Python FastAPI (CPU만, 경량 모델)
```

### 1. 통합 서버 설정

#### Docker Compose (로컬 개발)
```yaml
version: '3.8'
services:
  app:
    image: investment-choi:latest
    ports:
      - "8080:8080"
    environment:
      - SPRING_DATASOURCE_URL=jdbc:mariadb://db:3306/investment
      - REDIS_HOST=redis
    depends_on:
      - db
      - redis
  
  db:
    image: mariadb:11.8
    environment:
      - MYSQL_ROOT_PASSWORD=root
      - MYSQL_DATABASE=investment
    volumes:
      - db_data:/var/lib/mysql
  
  redis:
    image: redis:7-alpine
    command: redis-server --maxmemory 2gb --maxmemory-policy allkeys-lru
  
  ai-service:
    build: ./ai-service
    ports:
      - "8000:8000"
    environment:
      - MODEL_TYPE=lightweight
      - USE_GPU=false

volumes:
  db_data:
```
