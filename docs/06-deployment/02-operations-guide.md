# 운영 가이드

## 1. 모니터링

### 1.1 애플리케이션 로그
- **로그 경로**: `/LOG/investment-choi.log` (Kubernetes)
- **로그 형식**: 구조화된 JSON 로그
- **로그 레벨**: 
  - 프로덕션: INFO
  - 개발: DEBUG

### 1.2 주요 로그 이벤트
- 주문 실행: `INFO` 레벨
- 전략 실행: `INFO` 레벨
- 에러 발생: `ERROR` 레벨
- 외부 API 호출 실패: `WARN` 레벨

### 1.3 로그 분석
```bash
# 에러 로그 확인
grep ERROR /LOG/investment-choi.log

# 특정 계좌 로그 확인
grep "accountNo=12345678" /LOG/investment-choi.log

# 주문 실행 로그 확인
grep "주문 실행" /LOG/investment-choi.log
```

## 2. 성능 모니터링

### 2.1 메트릭 수집
- **Prometheus**: 메트릭 수집 (향후)
- **Grafana**: 대시보드 (향후)

### 2.2 주요 메트릭
- **응답 시간**: 평균, 95%ile, 99%ile
- **처리량**: 초당 요청 수 (TPS)
- **에러율**: 에러 발생 비율
- **JVM 메모리**: 힙 메모리 사용량
- **데이터베이스 연결**: 활성 연결 수

## 3. 장애 대응

### 3.1 일반적인 장애 시나리오

#### 3.1.1 데이터베이스 연결 실패
**증상**: 
- 애플리케이션 시작 실패
- 주기적인 연결 오류

**대응**:
1. 데이터베이스 서버 상태 확인
2. 네트워크 연결 확인
3. 연결 풀 설정 확인
4. 재시작

#### 3.1.2 외부 API 호출 실패
**증상**:
- 종목 분석 실패
- 시장 데이터 조회 실패

**대응**:
1. 외부 API 서버 상태 확인
2. API 키 유효성 확인
3. Rate Limit 확인
4. 모의 데이터 모드로 전환 (개발 환경)

#### 3.1.3 메모리 부족
**증상**:
- OutOfMemoryError 발생
- 응답 시간 급증

**대응**:
1. JVM 힙 메모리 증가
2. 메모리 누수 확인
3. 인스턴스 스케일 아웃

### 3.2 장애 복구 절차

1. **장애 감지**: 모니터링 알림 또는 사용자 신고
2. **원인 분석**: 로그 및 메트릭 확인
3. **임시 조치**: 서비스 복구 (재시작, 롤백 등)
4. **근본 원인 분석**: 장애 원인 파악
5. **재발 방지**: 개선 사항 적용

## 4. 백업 및 복구

### 4.1 데이터베이스 백업

#### 4.1.1 자동 백업 (권장)
```bash
# 매일 자동 백업 스크립트
mysqldump -u investment -p investment > backup_$(date +%Y%m%d).sql
```

#### 4.1.2 수동 백업
```bash
mysqldump -u investment -p investment > backup.sql
```

### 4.2 복구 절차

#### 4.2.1 전체 복구
```bash
mysql -u investment -p investment < backup.sql
```

#### 4.2.2 특정 테이블 복구
```bash
mysql -u investment -p investment < backup_table.sql
```

## 5. 용량 관리

### 5.1 데이터베이스 용량
- **주문 데이터**: 주기적 아카이빙 (1년 이상 데이터)

### 5.2 디스크 용량
