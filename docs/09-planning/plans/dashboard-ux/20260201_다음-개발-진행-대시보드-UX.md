## 3. 권장안: 대시보드·UX 1차 — 상세 계획 (수정)

### 3.1 목표

- **계좌 요약(국내·미국 구분)**: 대시보드에서 잔고/보유를 시장(KR/US)별로 구분해 표시.
- **자동투자 상태 카드**: 자동투자 ON/OFF, 오늘 시그널 건수(KR/US), 보유 포지션 수 등 한눈에 보기.

### 3.2 전제·제약 (수정)

- **한국투자증권 API**로 **미국주식 조회·매매가 가능**하므로, 계좌 요약 KR/US 구분은 **동일 API(잔고·보유종목 조회)** 를 활용한다.
- 구현 시 **한국투자증권 MCP**로 다음을 반드시 확인한 뒤 적용한다.
  - 잔고·보유종목 조회 API에서 **해외(미국) 포함 여부** 파라미터(예: `OVRS_ICLD_YN` 등) 및 **국내/해외 별도 조회** 가능 여부.
  - 응답 구조에서 **거래소·시장 구분** 필드(예: `EXCG_ID_DVSN_CD`, `KRX`/`NASD` 등)로 KR vs US 집계 가능 여부.
- 위 MCP 확인 결과에 따라:
  - **한 번의 조회로 국내+해외 모두 반환**되면: 응답의 시장 구분 필드로 KR/US 집계.
  - **국내/해외 별도 엔드포인트 또는 파라미터**가 있으면: KR 조회 + US 조회 각각 호출 후 대시보드에서 시장별로 표시.
- **자동투자 상태**는 기존 [PipelineSummaryService](src/main/java/com/investment/factor/service/PipelineSummaryService.java)·[TradingSetting](src/main/java/com/investment/domain/entity/TradingSetting.java) 데이터를 그대로 활용.

### 3.3 구현 단계

**1) 백엔드**

- **MCP 선행**: 한국투자증권 MCP로 잔고·보유종목 조회 API 스펙 확인(해외 포함 파라미터·응답 시장 구분 필드).
- **계좌 요약 시장 구분**:
  - `AccountService` 또는 `KoreaInvestmentAccountClient`: 필요 시 해외 포함 조회·시장 구분 파싱 추가. DTO에 시장별 집계(예: `balanceKr`/`balanceUs`, `positionsKr`/`positionsUs`) 또는 positions 목록에 `market` 필드 추가 후 대시보드에서 집계.
  - 기존 [BalanceAndPositionsDto](src/main/java/com/investment/account/dto/BalanceAndPositionsDto.java)·[AccountPositionDto](src/main/java/com/investment/account/dto/AccountPositionDto.java)에 시장 구분이 없으면, 응답 파싱 단계에서 거래소 코드로 KR/US 판별해 DTO 확장 또는 별도 Dashboard 요약 DTO에 시장별 집계 반영.
- **자동투자 상태**: [PipelineSummaryService.getSummary](src/main/java/com/investment/factor/service/PipelineSummaryService.java), [TradingSetting.autoTradingEnabled](src/main/java/com/investment/domain/entity/TradingSetting.java). DashboardController에서 `accountNo`·오늘 `basDt`로 조회 후 Model에 추가.
- **DashboardController**: 시장별 요약·자동투자 상태 DTO를 Model에 넣고, 예외 시 기존 잔고·보유·주문 카드는 유지(Fallback).

**2) 프론트 (dashboard.html)**

- 계좌 요약: "국내(KR)" / "미국(US)" 카드 또는 섹션 구분, 시장별 잔고·보유 건수(또는 금액) 표시.
- 자동투자 상태 카드: ON/OFF, 유니버스 수(KR/US), 시그널 건수(KR/US), 보유 포지션 수.
