# 화면·메뉴 기획서

## 개요

이 문서는 자동투자 시스템의 **확장 가능한 메뉴 구조**와 **메뉴별 화면 역할·요소**를 정의합니다. 메뉴는 이후 계속 확장될 수 있으므로 **설정/코드 기반** 구조(메뉴 ID, 순서, 권한, 라우트 매핑)를 권장합니다.

**참고**: [08-frontend-architecture.md](../02-architecture/08-frontend-architecture.md), [dashboard.html](../../src/main/resources/templates/dashboard.html) quick-action 구조를 메뉴 체계로 흡수·일원화합니다.

---

## 1. 설계 원칙

- **확장성 우선**: 새 메뉴 추가 시 기존 레이아웃·라우팅을 깨지 않고, 설정(또는 코드)에 메뉴 ID·순서·경로·권한만 추가.
- **일관된 레이아웃**: 모든 화면은 공통 **헤더(로고·사용자·로그아웃)**·**사이드/상단 메뉴**·**본문 영역** 구조. 본문 영역만 메뉴별로 교체.
- **API 연동**: 메뉴별 화면은 가능한 한 REST API와 1:1 대응. Thymeleaf 서버 렌더링과 REST 클라이언트 호출을 함께 고려.

- **국내 전략** / **미국 전략**: 기존 `strategies` 화면을 시장(KR/US)별로 분리하거나, 단일 화면 내 탭/필터로 시장 구분. 확장 시 다른 시장(예: 일본) 추가 가능.
- **뉴스·이벤트**: 확정 원천(DART·연합·네이버 / SEC·Reuters·Yahoo) 요약·필터·연동 상태.

### URL·계좌 타입 규칙

- **전역 계좌 탭**: 모든 메뉴 화면(로그인 사용자)에서 **모의계좌 | 실계좌** 탭을 메뉴 바로 아래에 표시. 탭 선택은 URL 쿼리 `serverType=1`(모의) / `serverType=0`(실계좌)로 유지. 기본값 `1`.
- **링크 정합성**: 메뉴 링크·빠른 액션·내부 링크에는 현재 `serverType`을 쿼리로 포함하여 화면 이동 시 계좌 타입이 유지되도록 함.
- **실제 처리 경로**: 대시보드 노출 경로는 `/`이며, 서버는 `/` 접근 시 쿼리 파라미터를 유지한 채 `/dashboard`로 리다이렉트함.

## 3. 메뉴별 화면 역할·요소

### 3.1 대시보드 (`/`)

- **목적**: 로그인 후 첫 화면. 모의계좌·실계좌를 **한 화면에서 구역으로 구분**해 계좌 요약·자동투자 상태·빠른 진입 제공.
- **주요 블록**:
  - **모의계좌 구역**: 모의계좌(serverType=1) 메인 계좌가 있으면 표시. 잔고·보유·자동투자 상태·빠른 액션(serverType=1 링크)·최근 주문 등.
  - **실계좌 구역**: 실계좌(serverType=0) 메인 계좌가 있으면 표시. 동일 구조로 해당 계좌 데이터만 표시.
  - 계좌가 하나도 없으면 빈 상태 안내 및 설정 링크.
- **API 연동**: `AccountService.getMainAccount(userId, "1")`·`getMainAccount(userId, "0")` 각각 조회, 잔고·보유·PipelineSummaryService.getSummary(서버 렌더링).

### 3.2 자동투자 현황 (`/auto-invest`)

- **목적**: 자동매수(통합 복합 로직: 파이프라인+로보) 현황·4단계 파이프라인(유니버스→시그널→자금관리→매매실행)·오늘의 시그널·체결 요약.
- **주요 블록**:
  - 파이프라인 단계별 카드: 유니버스 종목 수(KR/US), 시그널 건수(KR/US), 자금 배분 요약(설정 기반 단기·중기·장기 예상 배분 표시), 보유 포지션 수 — 실데이터 연동 완료.
  - 시그널 목록 테이블: 시장(KR/US), 종목, 팩터, 점수.
  - 보유 포지션 테이블: 시장, 종목, 수량, 진입가, 진입일.
- **API 연동**: PipelineSummaryService(서버 렌더링), 전략·유니버스·시그널·주문 API(정의 시).

### 3.3 국내 전략 (`/strategies/kr`)

- **목적**: 국내(KOSPI/KOSDAQ) 단기/중기/장기 전략 조회·상태 변경·성과.
- **계좌**: 계좌번호 입력 없음. **모의계좌(serverType=1)** 를 자동 사용. 미등록 시 "모의계좌를 등록해주세요" 안내 및 설정 링크.
- **주요 블록**:
  - 전략 목록(단/중/장기): 상태(ACTIVE/STOPPED/PAUSED), 비중, 최대/최소 금액, 성과 지표.
  - 유니버스/시그널 요약: 주도주 유니버스, 수급 점수 등(API 제공 시).
- **API 연동**: `GET/POST/PUT /api/v1/strategies?...&market=KR` (시장 파라미터 확장 시).

### 3.4 미국 전략 (`/strategies/us`)

- **목적**: 미국(NYSE/NASDAQ) 단기/중기/장기 전략 조회·상태 변경·성과.
- **계좌**: 계좌번호 입력 없음. **실계좌(serverType=0)** 를 자동 사용. 미등록 시 "실계좌를 등록해주세요" 안내 및 설정 링크.
- **주요 블록**: 국내 전략과 동일 구조, 시장만 US.
- **API 연동**: `GET/POST/PUT /api/v1/strategies?...&market=US`.

### 3.5 뉴스·이벤트 (`/news`)

- **목적**: 확정 원천(공시·뉴스·센티멘트) 요약·필터·연동 상태.
- **주요 블록**:
  - 원천별 탭/필터: Fact(DART/SEC), Speed(연합/Reuters), Buzz(네이버/Yahoo).
  - 목록: 제목, 원천, 시장, 종목 연관, 수집 시각, 감정/중요도(표시 시).
- **API 연동**: 뉴스·공시 목록 API(정의 시).

### 3.6 포트폴리오 (`/portfolio`)

- **목적**: 보유 종목·일별 트레이딩 포트폴리오 조회.
- **주요 블록**:
  - 보유 종목 테이블: 종목, 시장, 수량, 평균가, 현재가, 평가손익 등.
  - 트레이딩 포트폴리오: 거래일 선택, 추천 종목·진입가·손절가·목표가.
- **API 연동**: `GET /api/v1/accounts/{accountNo}/positions`, `GET /api/v1/trading-portfolios/{date}`.

### 3.7 주문·체결 (`/orders`)

- **목적**: 주문 목록·체결 내역·미체결 취소.
- **주요 블록**:
  - 주문 목록 테이블: 주문일시, 종목, 시장, 매수/매도, 수량, 가격, 상태, 체결가 등.
  - 필터: 기간, 상태, 시장.
- **API 연동**: `GET /api/v1/orders?accountNo=...`, `DELETE /api/v1/orders/{orderId}?...`.

### 3.8 설정 (`/mypage` 또는 `/settings`)

- **목적**: API 키·계좌·거래 설정·리스크 파라미터.
- **주요 블록**:
  - **계좌·API 연결**: 모의계좌/실계좌 각각 API Key, Secret, 계좌번호 입력·한 번에 저장. API 키 변경 시에만 비밀번호 입력.
  - **자동투자 설정**: 등록된 계좌 수(0/1/2)에 따라 분기.
    - **0개**: 빈 상태("아직 등록된 계좌가 없어요") + [계좌 설정으로 가기] CTA(앵커 `#accountsForm`).
    - **1개**: 해당 타입(모의 또는 실) 라벨 + 단일 폼(최대/최소 투자금액, 단기·중기·장기 비율, **자동투자** 토글 OFF/ON, **로보 어드바이저** 토글 OFF/ON, 거래 설정 저장).
    - **2개**: 세그먼트 컨트롤 "모의계좌 | 실계좌" + 선택한 타입의 단일 폼(동일 항목). 토글은 common.css `toggle-label`·`toggle-text-left`·`toggle-slider`·`toggle-text-right` 구조로 스위치 형태 표시.
  - **자동투자(통합 복합 로직) vs 로보 포함**: **자동매수** ON = 통합 복합 로직(공통 전처리 → 로보(ETF) 단계 → 파이프라인(개별종목) 단계) 1회 실행. **로보 어드바이저** ON = 위 통합 로직 내에서 로보(ETF) 단계 포함. 설정에서는 "자동매수 ON" 하나로 통합 로직을 켜고, "로보 포함 여부"만 옵션. UI에서 로보를 켜면 자동투자도 함께 켜지도록 연동.
  - **빈 상태·피드백**: 계좌 미등록 시 "해당 계좌를 먼저 등록해주세요" + [계좌 설정에서 등록하기] 링크. 저장 성공 시 "저장되었습니다." 인라인 표시.
- **API 연동**: `GET/PUT /api/v1/settings/{accountNo}`, `GET /api/v1/user/accounts/main?serverType=1|0`, API 키·계좌 관련 API.

### 3.9 백테스트 (`/backtest`)

- **목적**: 4단계 파이프라인 백테스트·로보 어드바이저 동적 자산배분 백테스트 실행·결과 확인. 실행 전 백테스트 결과(로보 리밸런싱 직전 검증) 노출 가능.
- **주요 블록**:
  - **모드 선택**: "4단계 파이프라인 백테스트" | "로보어드바이저 백테스트".
  - **4단계**: 기간·시장·전략·초기자본 → 메트릭·수익 곡선·거래 목록.
  - **로보**: 간단 모드(기간·초기자본) + 고급 설정(모멘텀 기간·MA·Top N·리밸런싱 주기·수수료/슬리피지). 결과: 한 줄 해석·메트릭(CAGR·MDD·Sharpe·Calmar·회전율·벤치마크)·수익 곡선 vs 벤치마크·리밸런싱 이력.
- **API 연동**: `POST /api/v1/backtest`, `POST /api/v1/backtest/robo`, `GET /api/v1/backtest/robo/last-pre-execution?accountNo=xxx`.

## 4. 공통 레이아웃

- **모든 메뉴 화면은 layout-header + layout-menu 사용**: 인증 후 접근하는 화면(대시보드, 자동투자 현황, 국내/미국 전략, 뉴스·이벤트, 포트폴리오, 주문·체결, 스케줄 현황, 백테스트, 설정, 마이페이지)은 Thymeleaf fragment `fragments/layout-header`와 `fragments/layout-menu`를 포함하고, 본문만 메뉴별로 교체한다.
- **헤더**: 로고(클릭 시 대시보드 `/` 이동, `serverType` 쿼리 유지), 서비스명, 사용자 표시(또는 계좌 요약), 마이페이지·로그아웃 링크.
- **사이드 메뉴(또는 상단 탭)**: 위 메뉴 트리 순서대로 링크. 메뉴 ID 기반으로 활성 상태 표시. 각 링크에 `serverType` 쿼리 포함.
- **계좌 타입 탭**: 메뉴 바로 아래에 **모의계좌 | 실계좌** 탭 표시(로그인 사용자만). 탭 클릭 시 현재 경로 유지·`serverType`만 변경해 이동.
- **본문 영역**: 메뉴별 콘텐츠. 카드·테이블·필터 등. 페이지 제목용 `<h1 class="page-title">`는 사용하지 않음(레이아웃 정리).

## 5. 확장 규칙

- **새 메뉴 추가 시**:
  1. 메뉴 ID·표시명·경로·순서를 정의.
  2. 설정 파일(예: `menu-config.yml`) 또는 코드(예: `MenuConfig.java`)에 항목 추가.
  3. 라우팅: Spring MVC의 경우 컨트롤러에 `@GetMapping("/new-path")` 및 뷰 이름 매핑.
  4. 권한: 메뉴별 접근 제어가 필요하면 메뉴 ID와 역할 매핑 추가.
- **기존 메뉴 순서/표시명 변경**: 설정/코드에서 순서·표시명만 수정. URL 변경 시 리다이렉트 규칙 추가 권장.
