# Product Requirements Document (PRD)

## 문서 개요

이 문서는 Investment Choi 프로젝트의 제품 요구사항을 통합한 고수준 요약 문서입니다. 상세한 요구사항은 [기능 요구사항](./01-requirements/02-functional-requirements.md) 및 [비기능 요구사항](./01-requirements/03-non-functional-requirements.md) 문서를 참조하세요.

## 1. 프로젝트 개요

### 1.1 프로젝트명
**Investment Choi** - 주식 투자 수익 분석 및 자동 매매 시스템

### 1.2 프로젝트 목적
한국투자증권 KIS Developers (Open API)를 활용하여 **사람이 개입하지 않아도 되는 자동투자수익**을 목표로, 국내·미국 주식을 하나의 인터페이스로 통합 관리하는 시스템을 구축합니다.

### 1.3 제품 비전
- **핵심 목표**: **자동투자수익** — 사람 개입 없이 수익 극대화.
- **포지셔닝**: 감이 아닌 **퀀트 알고리즘·수학적 모델링** 기반의 **최상위 공격형 로보어드바이저** (MDD -15% 이내, CAGR 30% 이상 목표).
- **엔진 성격**: 일반 자산배분 엔진이 아닌 **헤지펀드형 퀀트(Quant) 트레이딩 엔진** 설계.
- **4단계 파이프라인**: **유니버스 선정 → 시그널 생성 → 자금 관리 → 매매 실행** — 시장별(한국/미국)·분야별 상이한 수학적 모델 적용.
- **시장**: 국내 주식(KR) / 미국 주식(US) — 미시구조 차이에 따른 시장별·분류별 차별화된 알고리즘 적용.
- **주문 체결 엔진**: 한국투자증권 KIS Open API (국내 증권사 중 REST·WebSocket 가장 안정적).
- **투자 기간**: 단기/중기/장기 전략을 시장별로 다르게 운영.
- **데이터 원천**: 확정된 **공시/데이터(Fact)**·**뉴스/속보(Speed)**·**센티멘트/수급(Buzz)** 원천만 파이프라인에 연결.
- **개발 원칙**: 모든 설계·개발은 **확장성** 우선.

## 2. 제품 목표

### 2.1 핵심 목표
1. **자동투자수익**: 사람 개입 없이 퀀트 엔진 기반 자동 매매로 수익 극대화 (MDD -15% 이내, CAGR 30%+ 목표)
2. **4단계 파이프라인**: 유니버스 선정 → 시그널 생성 → 자금 관리 → 매매 실행 (시장별·분류별 알고리즘 적용)
3. **국내·미국 통합**: 한국(KOSPI/KOSDAQ)·미국(NYSE/NASDAQ) 주식 단일 인터페이스·통합 증거금 관리
4. **전략 기반 자동 매매**: 단기/중기/장기 전략을 시장별로 다르게 운영
5. **공시·뉴스·센티멘트 연동**: 확정 원천(DART·연합·네이버 / SEC·Reuters·Yahoo)만 파이프라인 연결
6. **리스크 관리**: 투자금액 제한, 손절가·ATR Trailing Stop, 켈리·변동성 역가중 등
7. **실시간 모니터링**: WebSocket 우선 시세·체결, 계좌·보유·주문 실시간 조회

### 2.2 성공 지표
- **기능 완성도**: 핵심 기능 구현 완료율 100%
- **성능**: API 응답 시간 평균 500ms 이하, 95%ile 1초 이하
- **안정성**: 시스템 가동률 99.0% 이상
- **보안**: 보안 취약점 0건
- **코드 품질**: 테스트 커버리지 라인 80% 이상, 브랜치 70% 이상

## 3. 대상 사용자

### 3.1 주요 사용자
- **개인 투자자**: 자동화된 투자 분석 및 추천을 원하는 개인 투자자
- **퀀트 트레이더**: 정량적 분석 기반 자동 매매를 수행하는 트레이더
- **자동 매매 시스템 운영자**: 전략 기반 자동 매매 시스템을 운영하는 사용자

### 3.2 사용자 요구사항
- 직관적인 웹 인터페이스
- REST API를 통한 프로그래밍 방식 접근
- 실시간 계좌 및 주문 현황 조회
- 투자 전략의 유연한 설정 및 관리

## 5. 비기능 요구사항 요약

- **API 응답 시간**: 평균 500ms 이하, 95%ile 1초 이하
- **주문 실행 시간**: 2초 이하
- **종목 분석 시간**: 3초 이하
- **웹 페이지 로딩 시간**: 2초 이하
- **처리량**: 최소 50 TPS, 동시 사용자 10명 이상

- **장애 감지 시간**: 5분 이내
- **복구 시간**: 30분 이내

**상세 내용**: [가용성 요구사항](./01-requirements/03-non-functional-requirements.md#2-가용성-요구사항)

**상세 내용**: [확장성 요구사항](./01-requirements/03-non-functional-requirements.md#4-확장성-요구사항)

## 6. 제약 사항

### 6.1 기술적 제약
- **시장 데이터 조회 제한**: 한국투자증권 API 제약
  - 모의투자: 초당 2건
  - 실거래: 초당 20건
- **Java 버전**: Java 17 (SE) 사용
- **데이터베이스**: MariaDB 11.8.5 이상

### 6.2 비즈니스 제약
- 단일 계좌 관리 (다중 계좌는 향후 확장)
- 국내·미국 주식 지원 (한투 통합 증거금 활용)
- 파생상품 거래 미지원

## 7. 제외 사항

### 7.1 현재 버전에서 제외된 기능
- 다중 계좌 동시 관리
- 옵션/선물 등 파생상품 거래
- 실시간 시세 미연동 시 폴링 방식 (WebSocket 우선 권장)

### 7.2 향후 확장 가능 항목
- 모바일 앱 개발
- 다중 계좌 관리
- 추가 시장·팩터·메뉴 확장 (확장성 우선 설계)

## 8. 기술 스택

### 8.1 Backend
- **프레임워크**: Spring Boot 3.2.2
- **언어**: Java 17 (SE)
- **데이터베이스**: MariaDB 11.8.5
- **ORM**: Spring Data JPA / Hibernate
- **빌드 도구**: Gradle 8.x

### 8.2 Frontend
- **템플릿 엔진**: Thymeleaf 3.1.x
- **클라이언트 스크립트**: JavaScript ES5

### 8.3 외부 API
- **증권 API**: 한국투자증권 Open API
- **인증**: OAuth 2.0

### 8.4 인프라
- **캐시**: Redis (선택)
- **컨테이너**: Docker (선택)
- **모니터링**: Prometheus (선택)
